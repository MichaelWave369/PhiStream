# Gate B: local reference trace comparison (candidate)

**Goal:** compare ΦStream’s outputs on the **same local safetensors checkpoint**
against trace values produced by a **separate, user-identified reference runtime**.

The comparison engine is independently written. It does not invoke the
reference runtime, download weights, install libraries, upload files, or alter
the checkpoint. Reference provenance is **user-declared, not authenticated**.
A matching trace is evidence of an observed comparison, **not** proof that
the reference was genuinely independent.

## Prepare your own local checkpoint

PhiStream currently supports only its narrow canonical LlamaForCausalLM
architecture, from explicit local safetensors files; no GGUF/Ollama integration
or tokenizer exists. First inspect the checkpoint and the model license:

```powershell
python -m phistream.cli inspect-checkpoint "C:\models\local-llama" --llama-layout
python -m phistream.cli fingerprint-checkpoint "C:\models\local-llama" --output "benchmarks\local\weights-fingerprint.json"
```

The fingerprint command computes SHA256 over *every byte* of `config.json`
and all referenced safetensors shards, which may take substantial time for a
large model. It does **not** authenticate the source, revision, runtime or
license; record those independently. It does not write beside the checkpoint.

## Reference trace V1 contract

Use a separately run reference implementation to generate a JSON file matching
the following shape, using **the same exact weight files, model parameters,
prompt token IDs, and sequential greedy decoding**.

```json
{
  "schema": "PHISTREAM_REFERENCE_TRACE_V1",
  "reference": {
    "runtime": "Name of independent implementation",
    "version": "Version or commit",
    "execution_device": "cpu",
    "asserted_independent": true
  },
  "checkpoint_fingerprint": {
    "algorithm": "sha256",
    "files": {
      "config.json": "64_lowercase_hex_character_sha256",
      "model.safetensors": "64_lowercase_hex_character_sha256"
    }
  },
  "prompt_token_ids": [1, 2, 3],
  "expected_generated_token_ids": [4, 5],
  "logit_probes": [
    {"4": 1.231, "0": -0.151},
    {"5": 0.934, "0": -0.019}
  ],
  "atol": 0.0001,
  "rtol": 0.0001
}
```

The digest strings above are **placeholders**, not actual hashes. Replace with
values from the fingerprint command. This illustration uses only two steps;
an eligible-length candidate must contain **at least 32** reference steps.

A probe map contains up to 128 sampled vocabulary index → floating-point logit
values for **one** expected generated token. A complete logit vector is not
required, so receipts honestly label coverage as `SPARSE_COORDINATES_ONLY`.
Use a spread of sampled coordinates and the expected greedy ID; don't infer
unsampled logit equality from a match. The trace is capped at 8 MiB, 128 steps,
2048 prompt IDs and positive finite, bounded tolerances.

Reference implementers should record logits **after the entire prompt, then
after each teacher-forced preceding expected token**. The comparator reads the
reference’s expected next token at every step, even if PhiStream predicts a
different one; this keeps later positions comparable after the first mismatch.
Prompt IDs must be generated by an appropriately licensed tokenizer externally,
with identical normalization and special tokens. PhiStream never guesses IDs.

## Compare locally

```powershell
python -m phistream.cli compare-reference "C:\models\local-llama" --trace "benchmarks\local\reference-trace.json" --device cpu --output "benchmarks\local\reference-result.json"
```

CUDA runs require an available compatible GPU / CUDA PyTorch and must not be
used as a substitute for CPU parity investigation. The command fails closed if
requested CUDA is unavailable. `--output` never overwrites a receipt.

Before executing any checkpoint, the comparator checks **all** config and
safetensors file hashes against the reference file. A mismatch is an error,
not a partial result. Comparison receipts contain:
- Exact greedy token matches per step.
- Sampled logit values compared with absolute + relative tolerances.
- First-party computation device and self-declared reference identity.
- A `MISMATCH` status (nonzero exit) for disagreement.
- `MATCH_TOO_SHORT_USER_REFERENCE_UNVERIFIED` for matching traces shorter than 32 steps.
- `MATCH_USER_REFERENCE_UNVERIFIED` for ≥32 matching steps.

**None of these statuses authenticates reference independence.**
A match does not prove full-logit parity, licensed provenance, hardware VRAM
capacity, equivalence with Ollama's GGUF weights, or performance superiority
over AirLLM or any other engine.

## Security and publication

No model weights or reference traces are committed or uploaded automatically.
Use `benchmarks/local/` for generated JSON receipts (already gitignored).
Be mindful that the reference file may reveal model identity, hashes and output
token IDs; publishing either trace or receipt requires a deliberate review.

This step adds the test harness for real-model verification. **No actual
pretrained checkpoint or independently authenticated reference has yet been
executed in PhiStream's GitHub CI.** The automated tests use deliberately
untrained synthetic checkpoints and an independent full-sequence PyTorch
test reference. Those are valuable for regression testing, not real-model proof.

## What is still needed

1. Choose a small, explicitly licensed compatible Llama safetensors checkpoint.
2. Record a named independent runtime/version and exact model revision.
3. Produce at least 32 reference greedy IDs and sampled raw logits from the
   same weights and prompt, without deriving them from PhiStream.
4. Run the comparator on that user's machine and inspect mismatches.
5. Only then consider an externally reviewed real-checkpoint parity gate and
   GPU speed benchmark.

These steps intentionally cannot be declared completed by the unit tests.
